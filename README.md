# japan-park-env-similarity
Machine-learning pipeline for nationwide environmental similarity mapping of protected areas. Demonstrated across 35 Japanese national parks with reproducible, transferable code.

## Overview

This repository contains the code and data associated with the following manuscript:

> Ise H. & Kamada M. (manuscript in preparation). Physical environmental indicators of protected area representativeness: a machine-learning approach across 35 Japanese national parks. *Ecological Indicators*.

The pipeline trains a park-specific XGBoost classifier for each of Japan's 35 national parks using multidimensional physical environmental variables (climate, topography, geology, micro-landforms) integrated within an H3 hexagonal grid framework. Spatially grouped nested cross-validation is applied to produce unbiased performance estimates, and SHAP values are used to interpret variable contributions. Park-specific models are then extrapolated nationwide to generate continuous environmental similarity surfaces.

## Data preparation workflow

### 1. H3 grid generation

A nationwide H3 hexagonal grid (resolution 9, ~0.1 km² per cell) covering the Japanese archipelago was generated using the H3 library. This step is not included in this repository.

### 2. Spatial joins (DuckDB SQL)

Environmental variables from multiple source datasets were integrated with the H3 grid using area-dominant overlay (largest intersection area wins). Each SQL script in `sql/` handles one data source and outputs a parquet file. The scripts should be run in the following order:

| Script | Input | Output | Description |
|--------|-------|--------|-------------|
| `duckdb_sp_join_np_class_h3.sql` | `jpn_nps.parquet` | `h3_jpn_res9_with_nationalpark.parquet` | Assigns national park name and zone classification to each H3 cell |
| `duckdb_sp_join_chishitsu_h3.sql` | Seamless geological map (GSJ-AIST) | `h3_jpn_res9_with_chishitsu.parquet` | Assigns lithology, geological group and formation age |
| `duckdb_sp_join_bichikei_h3.sql` | Landform classification 250m mesh (NIED) | `h3_jpn_res9_with_bichikei.parquet` | Assigns micro-landform class |
| `duckdb_sp_join_climate_h3.sql` | Climate mesh data (MLIT G02 v3.0) | `h3_jpn_res9_with_climate.parquet` | Assigns annual precipitation, temperature and snow depth |
| `merge_all.sql` | All above outputs | `merged_result.parquet` | Merges all joined datasets into a single table |

**Note:** Elevation and slope were derived from the ALOS World 3D 30m DEM using QGIS spatial analysis tools and are not included as SQL scripts.

### 3. Missing value imputation (DuckDB SQL)

`duckdb_impute_missing_value_20250521.sql` applies a spatially-constrained hierarchical imputation strategy to the merged dataset:

1. For each H3 cell with missing values, the nearest neighbouring cells within a radius of 10 H3 rings are identified
2. The average value from the closest neighbours with valid data is used to fill missing values
3. If no neighbours have valid data, the national mean is used as a fallback

**Data correction note:** A source-DEM coverage gap affecting the Yaeyama Islands region (Iriomote-Ishigaki and part of Ogasawara) caused elevation and slope values for those cells to fall back to the nationwide mean under rule 3 above. This has been corrected in the current `h3_jpn_res9_source_imputed.parquet`, and all 35 park-specific models have been retrained on the corrected dataset.

Output: `h3_jpn_res9_source_imputed.parquet`

### 4. Processed input data (Zenodo)

The two processed H3 datasets used as direct inputs to the modeling notebooks are deposited on Zenodo (https://doi.org/10.5281/zenodo.20053614) and should be placed in `data/interim/` before running the notebooks:

| File | Generated by | Description |
|------|-------------|-------------|
| `h3_jpn_res9_source_imputed.parquet` | Step 3 above | Merged and imputed environmental dataset for all H3 cells across Japan |
| `h3_jpn_res9_processed.parquet` | `01_preprocessing.ipynb` | Preprocessed dataset with English park name slugs and one-hot encoded categorical variables; direct input to `02_modeling.ipynb` |

## Modeling workflow (Jupyter Notebooks)

All notebooks are in the `notebooks/` directory and should be run in order.

### config.py

Shared configuration for all notebooks. Edit `DATA_DIR` and `OUTPUT_DIR` to match your environment before running.

```python
DATA_DIR   = Path("../data/interim")   # Location of h3_jpn_res9_source_imputed.parquet
OUTPUT_DIR = Path("../data/results")   # Per-park model output directory
PAPER_DIR  = Path("../paper_outputs")  # Tables and figures
```

Also contains `PARK_NAME_MAP` (Japanese → English slug mapping, used only in preprocessing) and `PARKS` (list of English slugs used in all downstream notebooks).

### 01_preprocessing.ipynb

- Loads `h3_jpn_res9_source_imputed.parquet`
- Translates Japanese park names in the `NAME` column to English slugs (the only step that uses Japanese text; all downstream notebooks use English identifiers exclusively)
- Applies one-hot encoding to categorical variables (`bichikei_en`, `group_en`)
- Saves `h3_jpn_res9_processed.parquet`

### 02_modeling.ipynb

Trains a park-specific XGBoost classifier for each of the 35 national parks. Key methodological features:

- **Block-matched negative sampling** with global mixing (`mix_global_frac=0.3`): negative samples are drawn to spatially match the distribution of positive samples, with 30% drawn at random from the whole country
- **Automatic spatial resolution tuning**: the H3 parent resolution is adjusted automatically within the range of resolutions 5 to 9 to ensure sufficient positive spatial groups for cross-validation
- **Greedy fold assignment with single-class repair**: folds are constructed to balance positive counts, then repaired to ensure every test fold contains both classes
- **Spatially grouped nested cross-validation** with automatic per-fold gap relaxation (`gap_relax_steps=(1, 0)`)
- **CV-averaged threshold calibration**: the production threshold is determined as the mean of the F1-maximizing thresholds obtained within each outer cross-validation fold

After cross-validation, each model is refit on the full balanced dataset and applied nationwide to generate a continuous similarity surface. Outputs per park are written to `data/results/{slug}_prod_g8_gap1/`.

### 03_analysis_figures.ipynb

- Selects the best model run per park based on stability tier (T1 > T2 > T3)
- Aggregates cross-validation performance metrics (Table 2 in the manuscript)
- Computes SHAP-based feature importance at park and network scales
- Produces figures (global SHAP bar chart, park-level SHAP heatmap)
- Computes similarity-surface spatial statistics and structural type (Type I/II/III) classification (Supplementary Table S2)
- Generates the per-park elevation, climate, terrain, and lithology summary requested by Reviewer 3 (Supplementary Table S3)

### 04_figS1_similarity_maps.ipynb

Renders Supplementary Fig. S1 (nationwide environmental similarity surfaces for all 35 parks). Cells below each park's production threshold are left uncoloured; cells at or above threshold are coloured on a 5-class linear scale from the threshold to 1.0, avoiding the compressed appearance of the logarithmic scale used in earlier drafts.

## Model outputs

Per-park outputs are in `data/results/{slug}_prod_g8_gap1/`. Multiple candidate runs may exist per park (e.g. `_prod_g8_gap1`, `_prod_g8_gap1_rerun`, `_prod_g8_gap2`); `03_analysis_figures.ipynb` selects the best run automatically based on the tier criteria described in the manuscript.

| File | Included in repository | Description |
|------|----------------------|-------------|
| `{slug}_metadata_cv.json` | ✅ GitHub | Model parameters, performance metrics and threshold |
| `{slug}_similarity_scores_cv.csv` | ✅ Zenodo | H3 cell IDs with similarity scores for all of Japan |
| `{slug}_xgb_model_cv.joblib` | ✅ Zenodo | Trained XGBoost model |
| `{slug}_nationwide_similarity_cv.parquet` | ✅ Zenodo | Full nationwide dataset with similarity scores and binary labels |

All model outputs, processed input data, and trained models are deposited at Zenodo: https://doi.org/10.5281/zenodo.20053614

The dataset is distributed across multiple archive files. After downloading all parts, extract them into the repository root so that the `data/` directory structure is restored.

## Reproducibility note

Model outputs may differ slightly from those reported in the manuscript if the pipeline is re-run, due to stochastic elements in the negative sampling procedure. The results reported in the manuscript were obtained using the output files deposited at Zenodo (see above).
